# Что изменено относительно оригинала 1.0.6

Версия: `1.0.6-personal.7`.

## personal.7 — авторы синхронизации на одной кнопке (Vencord)

- Когда uploader и maker — разные люди, оба указаны на одной кнопке («Sync: @alice & @bob», ведёт на
  uploader'а), а обложка в карточке становится ссылкой на maker'а. Вторая кнопка свободна — туда встаёт
  «Using DiscordLyrics».
- Если обложки нет или ники не влезают в 32 символа — по кнопке на каждого, чтобы никто не остался без
  упоминания и ссылки. 3 новых теста.

## personal.6 — карточка Rich Presence реально видна (Vencord)

- Причина, по которой карточку никто не видел (и ты тоже): оригинал отправлял активность с
  `application_id: "0"` и Spotify-ключами картинок. Все плагины Vencord, чья карточка видна другим
  (CustomRPC, MusicRichPresence), используют настоящий ID приложения Discord.
- Новая настройка `rpcAppId` (+ встроенный ID, если он задан в сборке). Обложки теперь внешние ассеты
  этого приложения (`mp:external/...`), как в MusicRichPresence.
- Без ID карточка не отправляется, и **Spicy Lyrics не используется**: иначе текст Spicy был бы в статусе
  без видимой атрибуции, что нарушает их условия. До этой версии так и было — исправлено.

## personal.5 — кнопка «Using DiscordLyrics» (Vencord)

- Настройка `rpcShowPluginButton` (по умолчанию выключена): кнопка в Rich Presence со ссылкой на
  github.com/sh1guchi/DiscordLyrics. Занимает только свободное место: обязательные ссылки на авторов
  синхронизации Spicy Lyrics идут первыми, а у Discord максимум 2 кнопки.
- Карточка обновляется сразу при переключении настройки, без смены трека. 6 новых тестов.

## personal.4 — запросы текстов через прокси (Vencord)

- Все запросы нативной части (LRCLIB, Spicy Lyrics, обложки iTunes) теперь идут через сетевой стек
  Chromium (отдельная сессия Electron в памяти), а не через `fetch` из Node.js. Node игнорирует
  системный прокси Windows, поэтому с VPN-клиентом в режиме «системный прокси» сам Discord работал,
  а тексты — нет.
- Настройка `lyricsProxy`: пусто — системный прокси (как у Discord), `http://…`/`socks5://…` — свой прокси,
  `direct` — напрямую. Некорректное значение безопасно откатывается к системному.
- Проверено в настоящем Electron 42.11.4 (версия твоего Discord): LRCLIB, Spicy Lyrics и iTunes
  отвечают во всех трёх режимах; мусорное значение настройки запросы не ломает.

## personal.3 — тексты из Spicy Lyrics (Vencord)

- Новый источник через официальный API Spicy Lyrics (`GET /v1/lyrics/{spotifyTrackId}`) с личным ключом
  (настройка `spicyLyricsKey`). Порядок: Spicy Lyrics → LRCLIB. Без ключа поведение не меняется.
- Синхронизация по словам: слоги склеиваются в слова, а куски длинной строки переключаются, когда поётся
  первое слово куска (с тем же минимумом 1,2 с на кусок).
- Атрибуция по правилам Spicy: провайдер в заголовке Rich Presence, для синхронизаций от сообщества —
  кнопки со ссылками на uploader и maker (один человек — одна кнопка). Без Rich Presence Spicy не используется.
- 401/403 — ключ помечается отклонённым (одно уведомление), до смены ключа только LRCLIB; 429 и 5xx —
  пауза на `Retry-After` (минимум 60 с / 30 с). Ответы `Static` (без таймингов) уходят в LRCLIB.
- Запрос делается из нативной части (без CORS), ключ никогда не пишется в лог; кэш только в памяти
  (правило Spicy — не хранить дольше 30 дней).
- Проверено: 11 сценариев на заглушках (включая тайминг по словам, атрибуцию, 404/429/401, выключенный
  Rich Presence, трек без ID, отсутствие ключа в логе), `tsc`/`eslint`/сборка Vencord. С настоящим ключом
  не проверялось — ключ у владельца.

## personal.2 — длинные строки больше не обрезаются (Vencord)

Длинная строка делится на куски примерно по 46 символов (столько влезает в пузырь статуса), и куски
показываются по очереди. В оригинале хвост строки часто не показывался вообще. Причин было три:
время кусков считалось с лишним вычитанием сдвига в 650 мс; хвост ставился в самый конец строки,
потому что время делилось пропорционально буквам; перед проигрышем точки включались раньше хвоста.

Теперь:
- куски примерно равной длины («24 + 23» вместо «40 + 7», хвост больше не одно слово);
- равное время на кусок, от момента появления строки на экране;
- каждый кусок держится не меньше 1,2 с, чтобы пережить лимит в 1 запрос/с;
- если строка слишком быстрая для листания, она показывается целиком (до 128 символов). В пузыре
  профиля Discord может обрезать её визуально, но в самом статусе текст полный;
- точки перед проигрышем включаются только после того, как показаны все куски.

Прогон на реальных песнях, строки, показанные полностью (у тебя / у других):

| Песня | Было | Стало |
|---|---|---|
| Eminem — Rap God | 95/148 | 148/148 |
| Oxxxymiron — Где нас нет | 69/84 | 84/84 |
| Queen — Bohemian Rhapsody | 40/50 | 50/50 |

BD-версия строки не листает, а показывает целиком до 128 символов, её это не касалось.

## Обе версии

- **Windows-фолбэк:** один постоянный процесс PowerShell вместо нового процесса каждые 2 секунды.
  Он запускается, только когда Discord не видит Spotify, и сам закрывается через минуту простоя.
- **Точность в Windows-фолбэке:** Windows отдаёт позицию трека, которая обновляется раз в несколько секунд
  (проверено: одно и то же значение 4 секунды подряд), поэтому в оригинале текст отставал до ~4 с.
  Теперь позиция досчитывается по `LastUpdatedTime` и между опросами.
- **Кириллица и другие не-латинские названия:** в сравнении названий было `[^a-z0-9]`, из-за чего любые
  два русских трека считались одинаковыми (подтягивались альбом и длительность от предыдущего), а поиск
  обложки для них был случайным. Теперь `\p{L}\p{N}`.
- Вывод PowerShell явно в UTF-8. На этом ПК оригинал тоже выводил кириллицу нормально (похоже, включена
  системная UTF-8), так что это страховка для обычной настройки Windows.
- **Поиск текста:** результат поиска LRCLIB принимается, только если совпадает название (и есть ещё
  совпадение по исполнителю или длительности), а не просто первый найденный. Исправлено сравнение
  исполнителей при нескольких артистах. «with» в названии вырезается только в скобках («Song - With You»
  больше не обрезается).
- **Кэш текстов** (50 последних треков), независимый от источника данных.
- **Автообновление удалено.** Оно скачивало `.exe` из релиза автора и запускало его без проверки подписи
  или хеша — и перезаписало бы эту версию.

## BetterDiscord

- Исправлен спам запросами на паузе (флаг `force` обходил и сравнение, и кулдаун).
- Пауза и возобновление больше не сбрасывают загруженный текст.
- Добавлен поисковый фолбэк LRCLIB (раньше был только в Vencord-версии).
- Обработка 429: ждёт `retry_after`, потом повторяет. Повторная сверка статуса не чаще раза в 30 с.
- Тики не накладываются друг на друга; зависший Discord-стейт (позиция ушла за конец трека) игнорируется.
- Spotify-активность определяется точнее (раньше любая «Слушает» считалась Spotify).
- Строки LRC с несколькими метками времени (`[00:10][01:30] припев`) разбираются правильно.
- Панель настроек: префиксы, сдвиг текста, Windows-фолбэк.

## Vencord / Equicord

- Статус: 1 запрос на строчку вместо 3. Срок действия пишется один раз, время создания — только при
  переходе с пустого статуса.
- Минимальный интервал отправки 1 с (было 150 мс). Исправлен баг, из-за которого «срочные» обновления
  сбрасывали лимит и каждая вторая быстрая строчка уходила без задержки.
- Опрос Spotify Web API раз в 5 с вместо 0,5 с (Discord и так присылает события), при ошибке — пауза 30 с.
- Кэш поиска настроек статуса (раньше перебор всех настроек несколько раз за тик) и разбиения строки на куски.
- Ограничены кэши обложек (раньше росли всю сессию).
- Отладочный лог выключен по умолчанию, пишется в `%APPDATA%\DiscordLyrics\debug.log` с ротацией по 1 МБ
  (раньше — всегда, на Рабочий стол, без ограничения).
- Шрифт «wide» больше не ломает эмодзи; «Title Case» работает с кириллицей.
- Таймауты на сетевые запросы; обложка из iTunes берётся только при совпадении названия или исполнителя.
- Исправлены 2 ошибки типов, из-за которых плагин не проходил `tsc` в текущем Vencord.

## Установщик

Вместо ~70 КБ PowerShell/C#/VBS — `install.ps1` на ~100 строк: копирует файлы, для Vencord запускает
`pnpm install --frozen-lockfile` и `pnpm build`, `pnpm inject` — только по вопросу. Не убивает Discord,
не трогает `app.asar`, не клонирует непроверенный HEAD, не ставит глобально pnpm и не включает
`DANGEROUSLY_ALLOW_ALL_BUILDS`.
